# NVCI 新手任务向导产品需求说明

## 1. 产品目标

“新手任务向导”不是来源配置表单的另一种皮肤，而是连接研究目标、采集范围、执行计划、证据归档和技术参数分析的任务入口。它面向第一次使用 NVCI、不了解厂商采集路径与情报核心结构的产品经理，使其能够在五分钟内建立一张边界明确、可执行、可追踪、可复核的研究任务卡。

向导的首要成功指标是：用户无需理解来源配置、队列、快照、字段包等内部概念，也能正确发起任务，并始终知道当前卡在哪一步、为什么卡住、下一步需要谁处理。

## 2. 任务类型与研究模式

| 研究意图 | 厂商选择 | 产品线选择 | 系统模式 | 结果重点 |
|---|---:|---:|---|---|
| 单品牌全量归档与梯度分析 | 单选 | 单选或多选 | `vertical` | 产品树、系列、型号、彩页、URL、关键参数、证据缺口 |
| 多品牌同类产品对标 | 多选 | 必须选择兼容产品域 | `horizontal` | 每品牌主数据、型号级候选关系、关键偏离、证据回链 |
| 资料库增量更新 | 单选或多选 | 单选或多选 | `collection_update` | 哈希差异、新增/变化资料、失效路径与复用记录 |

系统根据厂商数量推荐模式，但不替用户做隐含决策。多厂商任务若产品线不属于同一产品域，必须阻止提交并要求拆分任务。

## 3. 向导流程

| 步骤 | 用户决策 | 系统责任 | 关键门禁 |
|---|---|---|---|
| 1. 任务目标 | 任务名称、决策问题、纵向/横向/增量更新 | 生成任务摘要与建议范围 | 决策问题不可为空 |
| 2. 厂商范围 | 单选或多选厂商 | 显示厂商路径健康、来源配置覆盖和最近验证时间 | 横向至少两个厂商 |
| 3. 产品线范围 | 单选或多选产品线/来源配置 | 显示系列、型号、资料数与审核状态 | 仅批准来源可执行；草稿来源进入准备清单 |
| 4. 执行方式 | 立即、一次预约、每日或每周 | 生成本地后台执行计划 | 预约时间必须晚于当前时间；周期任务必须有时间与时区 |
| 5. 分析范围 | 选择关键参数模板或自定义字段 | 建立研究任务和待批准字段范围 | 参数缺失标记为未披露/待复核，不自动填充 |
| 6. 确认提交 | 检查范围、资源量、风险和输出 | 保存任务卡，排队或等待时间触发 | 未批准来源、无 PDF URL、跨域冲突必须显式提示 |

## 4. 任务状态机

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| `draft` | 用户尚未完成或仅保存草稿 | 编辑、删除、继续配置 |
| `blocked` | 存在未批准来源或配置缺口 | 跳转来源准备、重新校验 |
| `scheduled` | 等待预约或周期触发 | 立即执行、修改时间、暂停 |
| `queued` | 已写入采集队列 | 查看排队位置、取消未认领任务 |
| `collecting` | 至少一个来源正在采集 | 查看分项状态和日志 |
| `analysis_pending` | 彩页采集完成，等待参数事实抽取或人工批准字段范围 | 提交/批准字段范围、启动受控分析 |
| `review_required` | 存在失效来源、未披露字段或证据冲突 | 处理审核队列 |
| `completed` | 采集与当前分析口径已完成 | 查看结果、导出、复制为新任务 |
| `failed` | 执行失败且无法自动恢复 | 查看原因、重试失败项 |
| `paused` | 周期任务暂停 | 恢复或归档 |

## 5. 执行架构选择

| 方案 | 权衡 | 运行成本 | 配置复杂度 |
|---|---|---|---|
| 复用 NAS 内现有采集 Worker 与队列 | 与当前来源配置、SHA-256 增量门禁和资料目录完全一致；适合本系统，支持浏览器关闭后继续执行 | 使用现有 NAS 资源，不产生按次 AI 任务成本 | 中等，需要增加任务编排和一次预约/周期规则 |
| 由外部任务服务定时调用 NVCI 接口 | 调度能力独立、扩展方便，但需要额外认证、网络可达和运维组件 | 取决于外部服务 | 较高，故障链条更长 |

当前版本基于第一种方案实现，因为 NVCI 已在 NAS 内拥有持久 Worker、来源审批门禁、队列和增量采集核心。系统保留任务 JSON 导出接口，未来可由外部调度服务接管而不改变用户任务模型。

## 6. 数据模型

任务卡保存为 `/data/onboarding-tasks.json`，每条任务至少包含：`taskId`、`title`、`decisionQuestion`、`mode`、`vendorIds`、`profileIds`、`execution`、`analysis`、`status`、`requestIds`、`researchTaskId`、`createdAt`、`updatedAt`、`lastTriggeredAt` 和 `nextRunAt`。

分析范围保存模板 ID、字段代码、范围依据和自动分析策略。向导提交后在 SQLite 情报核心创建研究任务；字段范围以待批准字段包进入治理流程。采集结果继续使用现有不可变快照、`document_manifest.csv`、五列表格、`scope.json`、`update_summary.csv` 和 SHA-256 证据链。

## 7. 结果页信息结构

结果页先显示任务健康度，而不是只显示“成功/失败”。任务健康度由来源准备率、采集完成率、资料变化、失败数、字段范围状态和待复核数构成。产品清单按厂商、产品线、系列、型号展示，并同时显示产品页 URL、资料页/PDF URL、资料状态与证据规则。

## 8. 异常与安全边界

系统不允许向导绕过来源样本检查和人工批准；不允许用户提交任意非 HTTPS URL 或白名单外域名；不允许把未披露解释为不支持；不允许在一次任务中把横向和纵向分析混为同一事实矩阵。预约任务到期但来源仍未批准时，任务进入 `blocked`，不会自动下载。

## 9. 首版验收标准

1. 用户可创建纵向或横向任务，选择一个或多个厂商、一个或多个已登记来源配置。
2. 支持立即执行、一次预约、每日和每周执行；浏览器关闭后由 NAS Worker 继续运行。
3. 向导提交时创建任务卡，并为分析范围创建 SQLite 研究任务与待批准字段包。
4. 任务详情可显示来源配置、厂商、产品线、系列、型号、产品 URL、PDF URL、执行状态和分析下一步。
5. 未批准来源、时间无效、横向厂商不足和没有选中参数字段时必须被明确阻止。
6. 既有来源配置、采集队列、快照与情报核心接口保持兼容，现有测试通过。
